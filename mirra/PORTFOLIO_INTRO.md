# MIRRA 作品集介绍文案

## 一句话介绍

MIRRA 是一个纯前端体验优先的美妆与消费品智能对比工具：粘贴两个商品链接，即可获得价格、定位、成分、功效、口碑与选购建议的一站式对照。

## 项目背景

消费者在购买美妆与日用消费品时，面对的信息往往分散在品牌官网、电商详情页、测评内容和用户评论中。传统比价页面解决了“多少钱”，却很少解释“为什么适合我”。

MIRRA 将分散的公开信息重新组织为消费者真正需要的判断框架：不只展示参数，还整合成分逻辑、使用场景、高频好评、吐槽短板与种草视角，帮助用户更快完成消费决策。

## 我的工作

- 从消费决策链路出发定义产品信息架构与对比维度
- 设计“梳妆镜双面对照”视觉概念和响应式交互系统
- 实现双链接输入、AI 分析状态、差异高亮、维度筛选与价格判断
- 使用本地存储完成可回看、可删除的对比历史
- 为无 API Key 场景设计完整演示模式，保证作品集访问体验
- 在服务端代理 AI 搜索请求，避免密钥暴露
- 明确不爬取、不绕过登录、保留来源与检索时间的合规边界

## 创新点

### 1. 从“参数对比”升级为“消费决策”

项目将产品定位、适用人群、成分配方、典型场景、公开口碑和购买建议统一到一套判断框架中，贴合快消、内容社区与电商运营对消费者洞察的需求。

### 2. 差异优先的信息层级

相同信息被弱化，关键差异通过粉色色块、中心决策缝和局部标记突出，让用户不需要逐行阅读所有文字。

### 3. 有边界感的 AI 体验

价格被描述为“公开信息中近期可见价格”，并展示检索时间与来源。AI 不伪装成实时数据库，而是承担公开信息整合与解释的角色。

### 4. 作品集可用性

未配置 API Key 时自动进入演示模式，招聘方可以直接体验完整流程；配置密钥后则切换为真实 AI 联网检索。

## 面试可展开的技术亮点

- Next.js App Router：静态页面与单个服务端 API 路由分离
- 严格 JSON Schema：约束 AI 输出的商品结构、对比维度和来源
- SSR/SSG 与客户端状态边界：历史记录只在浏览器读取，避免服务端环境污染
- `localStorage` 版本化存储：支持历史回看、去重、删除和上限控制
- 可访问性：语义表格、键盘焦点、抽屉焦点管理、`prefers-reduced-motion`
- 性能：字体本地托管、无大型 UI 库、按需服务端 AI 调用、结果不缓存
- 安全与合规：API Key 仅服务端读取，不抓取用户提交的商品页
